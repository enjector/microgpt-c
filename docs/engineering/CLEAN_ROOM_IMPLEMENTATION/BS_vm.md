# BS_vm — Behaviour Specification (Virtual Machine)

**Document ID:** BS-VM-001
**Version:** 1.0
**Status:** DRAFT

## RFC 2119

The key words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, MAY, and OPTIONAL in this document are to be interpreted as described in RFC 2119.

## 1. Scope

Behavioural contract of the public VM API: `vm_engine_create`, `_dispose`, `_load`, `_register_fn`, `_run`, `_result_*`, `_last_error`, `_dump_il`. The bytecode opcode semantics are defined in `FS_vm_bytecode.md`.

## 2. Type contracts

### 2.1 `vm_engine`

**Invariants:**
- INV-VM-001: `vm_engine_create()` returns NULL on OOM, otherwise an opaque handle.
- INV-VM-002: `vm_engine_dispose(e)` releases all resources owned by `e`; the pointer SHALL NOT be dereferenced afterwards.
- INV-VM-003: An engine is single-threaded; concurrent calls on the same handle are undefined.

### 2.2 `vm_native_fn`

**Invariants:**
- INV-VM-010: Native function signature is `double (*)(int argc, const double *argv)`. Re-entrancy into the same engine is undefined.

## 3. Operation contracts

### 3.1 `vm_engine_load(e, source)`

**Preconditions:** `source` non-NULL.

**Postconditions:** Compiles `source` into the engine's module after the 6-pass verifier. Returns 0 on success or a non-zero error code; on failure, `vm_engine_last_error(e)` SHALL return a description.

### 3.2 `vm_engine_register_fn(e, name, fn)`

**Preconditions:** Called BEFORE `vm_engine_load` if the function is referenced in the source.

**Postconditions:** Records the binding. Subsequent `opCALL_EXT_METHOD` resolution finds it.

### 3.2a `vm_engine_find_fn(e, name)` (V1.0.4 — REQ-VM-007)

**Preconditions:** `e` and `name` MAY be NULL — the function returns NULL safely.

**Postconditions:** Returns the previously-registered `vm_native_fn` for `name`, or NULL if not registered. Lookup is O(n) over the small registration table (typically ≤ 50 entries); not on the inner-loop hot path. Used by `pipeline_execute_vm` to resolve graph nodes' primitives.

### 3.3 `vm_engine_run(e, fn_name)`

**Preconditions:** `fn_name` is a function declared in the loaded module.

**Postconditions:** Executes the function. Returns 0 on success or a non-zero runtime error code. On success the result is accessible via `vm_engine_result_number / _string / _bool`.

### 3.4 `vm_engine_dump_il(e)`

**Postconditions:** Writes a human-readable IL trace to stdout. Used for debugging.

## 4. Invariants table

| ID | Invariant |
|---|---|
| INV-VM-001..003 | Engine lifecycle and single-threadedness. |
| INV-VM-010 | Native ABI is `double(int argc, const double *argv)`. |
| INV-VM-020 | `vm_engine_load` runs all six verifier passes; failure leaves the engine unloaded. |
| INV-VM-021 | The opcode enum is append-only within v1.x (see `FS_vm_bytecode.md` §10). |
| INV-VM-022 | `opXPATH` and `opJSON` are reserved tags whose runtime semantics are deferred (`GAP-VM-002`). |
| INV-VM-011 | `vm_engine_find_fn` is a pure function of `(e, name)` — it does not modify the engine state. Concurrent reads with a `vm_engine_register_fn` writer require external synchronisation; concurrent reads without writers are safe. (V1.0.4 — REQ-VM-007.) |

## 5. Errors

| ID | Function | Code | Conditions |
|---|---|---|---|
| ERR-VM-001 | `vm_engine_create` | NULL | OOM |
| ERR-VM-002 | `vm_engine_load` | non-zero | Lex / parse / verifier failure; consult `vm_engine_last_error` |
| ERR-VM-003 | `vm_engine_run` | non-zero | Runtime error (uncaught, native callback returned error, etc.) |
| ERR-VM-004 | `verb_*` family | one of `RESULT_CORE_VERB_ERROR_*` (2300–2306) | Sentence dispatch failures |

## 6. Concurrency

Per-engine single-threaded; multiple engines may run in parallel. Native callbacks MUST NOT call back into the same engine on the same thread.

## 8. Scenarios

### SCN-VM-001: Run learned code

A demo loads a function generated by the wiring/codegen organelle, registers a few native helpers, calls `vm_engine_run(e, "main")`, and reads the result via `vm_engine_result_number`.

### SCN-VM-002: VM-backed pipeline dispatch

A pipeline with INT/FLOAT primitives is executed via `pipeline_execute_vm(p, vm, inputs, outputs)`; each leaf node's `primitive` is resolved through `vm_engine_register_fn` and dispatched.
