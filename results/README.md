# `results/` — committed evaluation traces and training logs

This directory holds **the audit trail of experiment measurements** — per-position eval CSVs, training loss curves, and headline eval logs. It's committed to git for the same reasons `data/` is: so a future reader can verify the headline numbers cited in `experiments/EXX-*.md` against the raw per-position records.

## What goes here

| Pattern | Content |
|---|---|
| `<task>_<arch>_train.log` | Per-step training loss curves (e.g. `klotski_mono_train.log`) — verifies T6 compute-equivalence claims |
| `<task>_<arch>_eval.log` | Headline eval summary: solve rate, latency p99, audit-coverage |
| `<task>_<arch>_eval.csv` | Per-position records: `position_id, attempted_moves, solved, latency_ms, audit_trace_lines` |

Cross-reference: the corpora these were trained/evaluated on live in `data/EXX-*/` with `provenance.txt`.

## What does NOT go here

- **Trained checkpoints** (`*.ckpt`). Regenerable from `data/EXX-*/train.tsv` + training config. `.gitignore`d.
- **Build artefacts** (binaries, object files). `.gitignore`d.
- **Cache files** (`build/.oql_llm_cache/`, `build/.oql_oracle_cache/`). Implementation detail; corpora in `data/` are the canonical input.
- **Intermediate raw logs** from interactive debugging. Commit only the final, reproducible eval traces.

## Integrity check

The eval CSV row counts must match the corpus held-out canonical counts in `data/EXX-*/provenance.txt`:

```bash
# Should print 113 + 1 (header) for Klotski
wc -l results/klotski_*_eval.csv

# Should print 948 + 1 (header) for 15-puzzle
wc -l results/puzzle15_*_eval.csv
```

## Policy when adding new results

1. Use the `<task>_<arch>_*.{log,csv}` naming pattern.
2. Cross-reference from the experiment's Section 3 — every measurement number should cite a results/ file.
3. Keep CSVs to one row per held-out position (or one row per training step for `_train.log`). No aggregation here; aggregation is in the experiment's Section 3 table.
4. Commit results alongside (or immediately after) the experiment's Section 4 conclusion commit.

The discipline mirrors `data/` + the leakage-audit + pre-registration disciplines: **every headline number traces back to a per-position record that anyone can re-aggregate.**
